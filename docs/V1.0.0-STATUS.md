# V1.0.0 engineering status

## Release identity
- Application ID: `dev.vscodeandroid.pro`
- Version name/code: `1.0.0` / `100`
- Minimum Android API: 26
- Target/compile SDK: 35
- UI: native Android Jetpack Compose

## Implemented in this source tree
- Dark, responsive Compose workbench with activity rail, explorer panel, tabs, editor, panel and status bar.
- Open files through Android Storage Access Framework, with persistable read/write permission requests.
- Save changes back to an opened document URI; Save As uses Android's document creation picker.
- Multiple in-memory tabs, dirty indicators, new untitled documents and tab switching/closing.
- Current-document find, match counting and replace-all.
- Filename-based language-mode labels for 19 common file types.
- Dynamic line-number gutter based on document line count.
- Explicit UI disclosure that shell execution, language servers, build tools and debugger adapters are not connected.
- Android backup disabled and cleartext network traffic disallowed by manifest policy.
- Unit-test source for filename-to-language-mode mapping.
- CI workflow for unit tests and debug/release APK assembly.

## Not implemented — do not advertise as working
This application is not yet a complete or production-ready Android IDE. The following requested capabilities are absent:
- Real syntax highlighting, semantic tokens, code completion, hover, diagnostics or language-server protocol clients.
- Bundled or managed Python, Java or Node.js runtimes.
- An executable sandboxed shell/terminal or resource-limited process broker.
- Git repository operations, credential management or diff/merge UI.
- VS Code-compatible extension host, extension marketplace installation or extension sandbox.
- Debug Adapter Protocol, breakpoints, stepping, variable inspection or debugger adapters.
- Workspace tree browsing and recursive project file management; the current explorer lists open editor tabs.
- Project templates, task runner, formatter integration, refactoring, multi-cursor editing or code folding.
- Production signing, Play distribution readiness, accessibility certification or device-farm validation.

The language selector is a file-mode label only. It must not be interpreted as language intelligence or runtime availability. The terminal panel is informational and intentionally does not execute commands. Desktop VS Code extensions are not assumed to be Android-compatible.

## Security posture and remaining review
The app uses the Storage Access Framework rather than broad filesystem permissions. Backup and cleartext traffic are disabled. These are baseline controls, not a complete sandbox. No arbitrary code execution is currently provided. Before introducing runtimes, implement an isolated execution broker with explicit user consent, per-project storage, CPU/memory/time quotas, cancellation, environment disclosure and security testing. Review SAF provider behavior, dependency vulnerabilities, privacy disclosures and accessibility before public release.

## Build status
See `TEST-REPORT.md`. A release APK assembled by CI without signing credentials is not a distributable signed release. Configure protected signing secrets and a separate release-signing workflow before distribution.
